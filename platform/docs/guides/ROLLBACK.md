# دليل التراجع — سند

## المبدأ
كل نشر مسبوق بنسخة احتياطية مُتحقَّقة. التراجع = استعادة النسخة + وسم الإصدار السابق. لا حذف بيانات.

## SQLite (تطوير/staging)
1. أوقف الخدمة.
2. النسخ الاحتياطية في `data/backups/sanad-<timestamp>.db`.
3. استعد: انسخ النسخة المطلوبة فوق `data/sanad.db`.
4. تحقق: `PRAGMA integrity_check` (يفعله `scripts/backup.js` عند الإنشاء).
5. أعد التشغيل.

## PostgreSQL (إنتاج)
1. أوقف الخدمة (أو ضعها في وضع الصيانة).
2. استعد أحدث `pg_dump` سليم: `pg_restore -d $DATABASE_URL <dump>` إلى قاعدة جديدة، ثم بدّل الاتصال.
3. أعد نشر إصدار الكود السابق (وسم Git السابق).
4. تحقق: تشغيل `tests/security.test.js` + فحص لوحة CEO مقابل أرقام معروفة.

## معايير قرار التراجع
- فشل اختبارات الأمن/الصلاحيات بعد النشر.
- تسرّب حقل حساس (رواتب/تكلفة) لدور غير مصرّح.
- فقد/تلف بيانات في مطابقة الترحيل.
- تعذّر تسجيل الدخول لدور رئيسي.

## زمن الاسترجاع المستهدف
- staging: دقائق (نسخ ملف).
- إنتاج: حسب حجم `pg_restore` + مبدّل الاتصال.
