## التحقق الفعلي

- **2341/2341** في `npm test` النهائي بالتوازي الافتراضي، دون تخطي أو إلغاء، على Node
  24.19.0 وSQLite. شمل تسعة اختبارات جديدة مقارنة بـv5.75.
- فحص HTTP مستقل على قاعدة مؤقتة ذات سيناريوهات: **1152 طلبًا** عبر **18 دورًا**،
  32 صفحة و26 مسبار API و6 فحوص مساعد لكل دور، بلا اختلاف حالة أو قيم عرض خام أو
  مصطلحات محظورة. P95 محلي 7ms؛ ليس قياس حمل أو أداء إنتاجي.
- أُضيفت «مراجعة جودة الإيراد» بعد المسح إلى قائمة الفحص (أصبحت 33 صفحة). مصفوفة
  الصلاحيات النهائية غطتها عبر الأدوار كلها، ونجح اختبار HTTP لتحويل رابط الشخص إلى
  ملف المورد مع سنة 2025 وشهر 12 ورفض مستخدم غير مخول. الملف المركّز: **8/8**.
- المعجم: 81 ملف واجهة ورسائل 229 ملفًا، ناجح. الوثائق: 23 صفحة و42 ترحيلة و18 وحدة،
  ناجح. تركيب src/scripts: 278 ملفًا، ناجح. فحص فروقات Git: نظيف.
- كشف المسح الأول خمس مخالفات في تجهيز/توقعات QA. أُصلحت بمقابلة المنح والبذور
  الفعلية، مع اختبارات انحدار؛ لم تُوسع صلاحيات التطبيق ليصبح المسح أخضر.
- فشلت محاولة وسيطة من الاختبار الشامل داخل ناقل نتائج Node برسالة
  `Unable to deserialize cloned data due to invalid or unsupported version` على ملف
  السيناريوهات. نجح الملف منفردًا **8/8** ثم نجح الشامل **2341/2341** بالإعدادات نفسها.
  السبب الجذري غير مثبت؛ يسجل KI-105 ويتطلب التحقق على Node 22 في CI. لم يُحذف اختبار
  ولم يُخفض التوازي لإخفاء الفشل.

جميع عمليات الاختبار على قواعد مؤقتة/قواعد الاختبارات. نسخة مسح HTTP أوقفت ونظفت؛
المساعد محلي والبريد preview، دون اتصال نموذج خارجي أو إرسال بريد.

## الوصول والتسليم

موافقة المالك على الرفع قائمة. إعادة `git push origin claude/evc-platform-analysis-r5nsri`
إلى `https://github.com/rayanzafar/Q.view` توقفت لغياب مصادقة GitHub في أداة التنفيذ
(`could not read Username`). طلب ربط الإضافة عُرض سابقًا ولم يثبت اكتماله؛ لا موافقة
نصية إضافية مطلوبة. إكمال الاتصال الفعلي بالحساب هو ما يفتح مسار الرفع وCI.

بعد إكمال الاتصال: رفع الفرع المسموح، تحقق CI وPostgreSQL وE2E، تجربة الدفعة، ثم
إصدار مقيد فقط عبر `SANAD_RELEASE=1 npm run deploy` وبنسخة احتياطية إلزامية. الإنتاج
يبقى خاضعًا لتجربة المالك واعتماده، وفق بروتوكول المستودع؛ لا نشر مباشر من Railway.

## تجربة الدفعة

1. نفّذ رحلة الموظف والإيراد في `v5.75-qa.md` على QA المقبولة.
2. بحساب موظف أسندت له مهمة مرتبطة بمشروع خارج صلاحياته: يرى المهمة والسياق المحجوب
   بلا رابط؛ بعد عضوية صحيحة يظهر المشروع المسموح.
3. بسجل تجريبي مصنف وموظف حقيقي ذي اسم مشابه: لا يظهر التجريبي في إسناد العمل، ويبقى
   الحقيقي. افحص الأدمن ثم قائد القطاع، والربط من كل جهة.
4. ببيانات اصطناعية ذات قطاعين، راجع نطاق الفواتير والتحصيل والمبيعات عبر API المسموح؛
   الشاشة المالية القديمة ملغاة ولا تعود بهذه الدفعة.
5. بأدوار المكتب، طلب مهمة يعرض نموذجًا فقط؛ لا يظهر ملخص مخاطر مشاريع غير مخولة.
