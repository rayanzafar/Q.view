# دليل الإطلاق الإنتاجي — سند (GO-LIVE Runbook)

> هذا الدليل يجعل تجهيز الإنتاج **«زرّاً واحداً»**: الكود جاهز، والناقص أن يوفّر المالك البنية والأسرار ثم تُتَّبع الخطوات أدناه بالترتيب. الإنتاج **بيئة منفصلة تماماً** عن staging — لا يُعاد استخدام قاعدتها أو أسرارها.

> **قاعدة صارمة:** الإنتاج القديم `os.evcsol.com` (مشروع Railway `honest-spirit`) **قراءة فقط** — نسخة العميل الحيّة. لا نشر عليه ولا كتابة إطلاقاً. «إنتاج سند» الجديد خدمة/بيئة مستقلة.

---

## 0) المتطلبات التي يوفّرها المالك (عوائق خارجية)
- [ ] **خدمة/بيئة Railway إنتاجية** جديدة (منفصلة عن `sanad-staging`).
- [ ] **قاعدة Postgres إنتاجية** (Railway Postgres جديدة) → تعطي `DATABASE_URL`.
- [ ] **نطاق إنتاجي** (مثل `sanad.evcsol.com` أو تحويل مدروس لاحقاً) + شهادة TLS (Railway تُصدرها تلقائياً للنطاق المخصّص).
- [ ] **بيانات SMTP** لنطاق `@evcsol.com` (للبريد الحقيقي — اختياري للإطلاق، إلزامي للتقارير المُرسَلة).
- [ ] **إذن إطلاق صريح** من المالك (سياسة سند: الإنتاج لا يُطلق إلا بأمر صريح).

## 1) متغيّرات البيئة الإنتاجية (تُضبط في لوحة Railway ▸ Variables)
| المتغيّر | القيمة | ملاحظة |
|---|---|---|
| `NODE_ENV` | `production` | |
| `DATABASE_URL` | (من قاعدة الإنتاج) | Postgres الإنتاجية — **لا** قاعدة staging |
| `SESSION_SECRET` | `openssl rand -hex 32` | **إلزامي** — سرّ فريد للإنتاج |
| `SANAD_SEED_DEMO` | `0` | **يوقف كل بيانات/حسابات العرض** (حرج للإنتاج) |
| `SANAD_ADMIN_USER` | (اسم المدير الأول) | يُنشأ حساب مدير واحد عند أول إقلاع |
| `SANAD_ADMIN_PASS` | (كلمة مرور قوية مؤقتة) | يُطلب تغييرها عند أول دخول |
| `PLATFORM_URL` | `https://<نطاق الإنتاج>` | يظهر في روابط التقارير/البريد |
| `MAIL_TRANSPORT` | `preview` ثم `smtp` | ابدأ بـ`preview`؛ حوّل لـ`smtp` عند توفر بيانات البريد |
| `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM` | (من مزوّد البريد) | تُملأ عند تفعيل البريد الحقيقي |
| `FISCAL_YEAR` | `2026` | |

> الأسرار تبقى في لوحة Railway فقط — لا في git ولا في الصورة (يحرسها `.gitignore`/`.railwayignore`).

## 2) النشر
```sh
# من مجلد platform/، مع ربط الجلسة بخدمة/بيئة الإنتاج (لا staging):
railway up --ci -s <خدمة-الإنتاج>
```
- الإقلاع موحّد عبر `scripts/boot.sh`: هجرة المخطط → أدوار/صلاحيات → (يتخطّى بذر العرض لأن `SANAD_SEED_DEMO=0`) → إنشاء المدير الأول → تشغيل الخادم.
- Railway يفحص `/ready` (حتى 300ث). انتظر «Healthcheck succeeded».

## 3) التحقق بعد أول إقلاع
```sh
curl -s https://<نطاق الإنتاج>/ready         # يُتوقع {"ready":true}
```
- سجّل الدخول بـ`SANAD_ADMIN_USER` → النظام **يفرض تغيير كلمة المرور**. غيّرها فوراً.
- تأكّد أن قوائم البيانات **فارغة** (لا بيانات عرض) — هذا هو المتوقّع في الإنتاج قبل استيراد البيانات الحقيقية.

## 4) إدخال البيانات الحقيقية
- عبر **مركز الاستيراد** داخل التطبيق (لا بذر): ارفع ملفات Excel للهيكل/الموظفين/الفرص/المشاريع/العقود — المحوّلات الستة تتحقق ثم تطبّق مع إمكان التراجع.
- أنشئ حسابات المستخدمين الحقيقية من شاشة إدارة المستخدمين (بأدوارها ونطاقاتها).

## 5) النسخ الاحتياطي (إلزامي قبل أي عملية بيانات لاحقة)
```sh
DATABASE_URL="<قاعدة الإنتاج>" sh scripts/pg-backup.sh        # نسخة مضغوطة في data/backups
```
انظر `docs/guides/BACKUP-RESTORE-DRILL.md` لتدريب النسخ/الاستعادة الكامل.

## 6) المسح والأدلة
```sh
node scripts/sweep.mjs https://<نطاق الإنتاج>   # صفر تسريب/مصطلحات، صلاحيات مضبوطة
```
> ملاحظة بيئة: في بيئة تطوير معيّنة قد لا يمرّ `fetch` عبر بوّابة الوكيل؛ عندها استخدم مسح `curl` البديل الموثّق.

## 7) خطة التراجع (Rollback)
- Railway يحتفظ بتاريخ النشرات: **Deployments ▸ اختر النشرة السابقة ▸ Redeploy** (أسرع مسار).
- أو أعد النشر من وسم git السابق.
- لاستعادة البيانات: `docs/guides/BACKUP-RESTORE-DRILL.md`. تفاصيل أعمّ في `docs/guides/ROLLBACK.md`.

## 8) التحويل النهائي للنطاق (Cutover) — قرار منفصل
- الإنتاج القديم `os.evcsol.com` يبقى **قراءة فقط** حتى قرار تحويل صريح.
- عند الجاهزية: وجّه نطاق الإنتاج إلى خدمة سند الجديدة في Railway، مع نافذة صيانة معلنة ونسخة احتياطية طازجة قبلها مباشرة.

### مرجع سريع للاختلاف staging ↔ إنتاج
| | staging | إنتاج |
|---|---|---|
| `SANAD_SEED_DEMO` | غير مضبوط (يبذر عرضاً) | `0` (لا عرض) |
| الحسابات | 10 حسابات عرض | مدير أول من البيئة ثم حسابات حقيقية |
| البيانات | لقطة عرض معقّمة | استيراد حقيقي عبر التطبيق |
| القاعدة | Postgres staging | Postgres إنتاج مستقلة |
| الأسرار | أسرار staging | أسرار إنتاج فريدة |
