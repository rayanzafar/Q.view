Execute the release protocol via the **release-manager** agent (or inline if the change is small). **The law of deployment is `platform/docs/guides/DEPLOY-PIPELINE.md`** (post-incident 2026-08-11): (1) `/quality` must be fully green first; (2) deploy with the ONE command — `export SANAD_RELEASE=1 && npm run deploy` from `platform/` — it takes the mandatory pg-backup itself (record the dump filename it prints), deploys pinned to the app-service UUID, awaits `/ready`, checks boot logs for applied migrations, and sweeps the seeded demo roles; NEVER use `railway up`/`down`/`redeploy` directly (hook-blocked — `down` removes the ACTIVE deployment of the linked service, `redeploy` re-runs the last snapshot, and the CLI link state can silently point at the DATABASE); (3) `node scripts/evidence.mjs https://staging.os.evcsol.com` for affected pages/roles; (4) flip `docs/CHANGELOG.md` markers to deployed + local git tag `wp/<n>-deployed`. Any live deviation → roll back via the Railway dashboard (Deployments ▸ previous ▸ Redeploy) or a `railway variables --set … --service <svc>` source-redeploy — there is NO `railway rollback` command — then diagnose. Report: deployment id, gate results, backup filename, evidence paths, changelog entry.
