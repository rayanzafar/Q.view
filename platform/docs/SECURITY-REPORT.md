# تقرير الأمن — سند (إعادة البناء)

## 1. الفجوات الأصلية (من تحليل النظام القديم) ومعالجتها
| # | فجوة النظام القديم | المعالجة في سند الجديد | الحالة |
|---|---------------------|-------------------------|:---:|
| R1 | التفويض في المتصفح؛ `/api/state` يعيد كل البيانات لأي مستخدم | تفويض على الخادم حصريًا (`core/rbac.can`) + تقييد نطاق في الاستعلام (`scopeFilter`) | ✅ مغلق + مختبَر |
| R1ب | الرواتب/الهوامش/التكلفة تصل العميل ثم تُخفى بالواجهة | حجب على مستوى الحقل في الخادم (`redact`)؛ القيمة لا تغادر الخادم لغير المصرّح | ✅ مثبت (bd يتلقى null) |
| R2 | تعرّض عناوين IP عبر `/api/users` | IP معلّم حساسًا؛ يُنقّح لغير الأدمن | ✅ |
| R13 | حساب admin شخصي + كلمة مرور متداولة | حسابات أدوار منفصلة؛ scrypt؛ قفل؛ منع خفض الدور الذاتي (مبدئيًا) | 🟡 |

## 2. ضوابط الأمن المطبّقة
- **المصادقة:** scrypt (N=16384)، قفل بعد 6 محاولات لمدة 15 دقيقة، `must_change_pw`، سجل دخول بـ IP/UA.
- **الجلسات:** كوكي عشوائي HttpOnly, SameSite=Lax, Secure في الإنتاج، انتهاء صلاحية + إبطال.
- **التفويض:** `can(user, action, resource, target)` — القرار الوحيد؛ نطاقات company/sector/department/project/team/own؛ منح قابلة للتهيئة في `role_permission`.
- **حجب الحقول:** سجل `SENSITIVE_FIELDS` (salary/cost/margin/ip) يُنقّح كل استجابة حسب صلاحية الطالب.
- **التدقيق:** `audit_log` غير قابل للتعديل لكل كتابة/اعتماد/دخول/تصدير.
- **المدخلات:** استعلامات مُعامَلة (parameterized) حصريًا — لا حقن SQL. تحقق من المدخلات في الخدمات (ساعات، مبالغ، إلزام حقول).
- **الاعتمادات:** الصلاحية تُفحص عند الطلب وعند كل إجراء اعتماد (لا افتراض).

## 4. المتبقّي قبل الإطلاق
- توكن CSRF لنماذج الويب (الآن SameSite=Lax يخفّف).
- جولة اختبار اختراق مستقلة.
- تدوير الأسرار (SESSION_SECRET, DB, SMTP, AI) وإدارتها عبر خزنة أسرار.
- سياسة كلمات مرور + (اختياري) MFA/SSO.
- تحديد صلاحية self-service (منع خفض الدور/التعطيل الذاتي على الخادم — مصمَّم، يُؤكَّد بالاختبار).
